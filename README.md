# 山行清单

移动端优先、无需账号和后端的个人徒步管理 PWA。核心业务数据与用户照片保存在当前站点的 IndexedDB；生产版首次联网完成缓存后，可以断网冷启动和编辑。

## 启动

需要 Node.js 22.12+（本项目在 Windows、Node.js 24.18 上验证）。

```sh
npm ci
npm run dev
```

开发地址通常为 http://localhost:5173。**开发服务器不安装离线 Service Worker**。

验证实际离线版本：

```sh
npm run build
npm run preview -- --port 4173
```

打开 http://localhost:4173，在「我的 → 检查离线使用条件」确认缓存就绪，再断网重开。

本仓库的发布目标为 https://hiking-check.rweb.site/#/ 。推送 `main` 后，GitHub Actions 运行单元测试和构建，并将 `dist/` 发布到 GitHub Pages，保留现有 HTTPS 域名。局域网 HTTP 地址可以预览页面，但不能作为手机 PWA 离线安装的验收环境。保留相同域名、协议、端口才能继续访问同一份本地数据库；5173、4173 和线上站点的数据彼此独立。

替换旧版「徒步装备检查」后，如果曾安装过旧 PWA，请联网打开一次网址，再关闭该站点的所有标签页和主屏幕应用后重新打开，让新缓存生效。不要为了更新而清理站点数据。旧版 `hiking-gear-db` 数据库不会被删除，但不自动转换到新版 `shanxing` 数据库；原本地开发版的数据可通过新版完整备份导入线上站点。

## 页面与功能

| 页面 | 可用功能 |
| --- | --- |
| 首页 | 最近未完成行程、必带未装包提醒、未备齐食物数量、打包进度、预算与跨行程实际支出、到期保养、待购摘要、自愿演示数据 |
| 装备 | 名称/品牌/型号/本地照片、克重/数量/整数分价格、日期/状态/存放位置/备注/保养日期、自定义分类和逗号分隔标签、离线搜索与筛选、排序、复制、批量待维修/归档、CSV |
| 行程 | 行程与每日路线、距离/爬升/天气备注/紧急联系人、复制/删除、装备库添加/临时物品/模板复用、分类与遗漏筛选、三态打包、确认重置、负重拆分 |
| 餐食 | 可编辑食物库、每天四餐、多食物与份数、单餐或整天追加复制、每日与全程重量/热量/费用、用户热量目标、采购合并与备齐数量、补给点新增/修改/删除、区间携带估算、CSV |
| 费用 | 预算、实际记账及照片、分类占比、日均费用、主动关联装备、CSV；计划餐费不自动记账 |
| 复盘 | 装备是否使用/是否好用/是否替换、替换加入待购、路线心得、剩余食物及份数文字记录 |
| 待购 | 预计价格/重量/链接/优先级/原因、编辑与状态管理、确认实际购入信息、新建装备或同款增购、事务防重、临时装备替换、受保护的购买撤销 |
| 我的 | 离线资源检查、申请持久存储、完整含照片备份/校验恢复、模板详情编辑/去重预览、分类管理、版本与更新、备份提醒、演示数据 |

标签通过自由文本添加，在装备搜索框中搜索标签即可筛选。分类使用可搜索下拉选项，可在表单中打开分类管理并保留草稿；支持新增、重命名、排序、停用和迁移删除。

## 数据规则

- 数据库 `shanxing` 由 Dexie 管理，当前版本 3。v1→v2 补齐保养字段，v2→v3 增加分类目录、来源标识和设备元数据；升级应用不会删除数据库。
- 表：`gear`、`trips`、`items`、`templates`、`foods`、`meals`、`supplies`、`daily`、`procurement`、`expenses`、`wishes`、`reviews`、`attachments`、`categories`、`meta`。
- 装备/食物单件重量按整数克保存，单价与支出按整数分保存。拥有数量是整数；个人携带数量与食物份数允许 0.1 的步长。餐食预估金额按每个条目四舍五入到分后汇总。
- 行程条目保存名称、分类、重量、价格快照。装备库更新不会自动覆盖行程；计划中的行程可预览并逐字段确认同步名称、分类和重量，价格不变；已完成行程锁定打包与餐食编辑。需要修正时可主动把行程改回计划中。
- 基础重量 = 包内及本人公共装备的非消耗品 × 本人携带数量。出发背包 = 基础 + 其他消耗品 + 出发领取的计划食物 + 饮水。穿戴单列。食物只在餐食模块录入，打包里的消耗品用于燃料等其他物品。
- 餐食、采购和食物负重来自同一组 `meals`。途中补给发生在当天开始；每个区间起始携带重量包括此前领取但未来才食用的食物。不模拟小时级饮食消耗或实际水源变化。
- 餐食与路线绑定「第几天」。起始日期平移时，显示日期同步平移；缩短天数若会越过已有餐食、路线或补给安排，拒绝保存并提示先处理超出部分。
- 复制行程保留路线、条目与餐食快照，重建补给关联，重置检查；不复制实际费用、备齐数量与复盘。
- 删除被行程、模板、费用或购买记录引用的装备时改为归档。删除行程会事务删除所属条目/餐食/补给/采购/费用/复盘，并解除关联待购。
- 待购入库事务先检查购买状态，避免双击、重试、多标签页并发重复入库。临时条目替换保留数量、检查状态与备注。撤销受其他行程/模板/费用/购买记录引用或数量变动保护，不会静默删除新增变更。
- 装备购置统计与行程实际支出独立。主动关联装备的支出仍由用户填写实际记账金额，关联本身不会新增费用。

## 离线与备份

`vite-plugin-pwa` / Workbox 缓存 HTML、脚本、CSS 和图标，所有核心资源均为同源资源；使用系统字体，无字体 CDN。用户照片转为允许的图片类型 Data URL 后写入 IndexedDB 附件表，不保存在线图片地址。

网络状态、缓存就绪状态、本机保存结果分别展示。页面在缓存注册失败时给出原因。「我的」检查预缓存里是否存在核心 HTML、脚本、样式和图标。新版本等待用户确认刷新，不自动打断编辑。

备份格式为 `shanxing-backup`，格式版本为 `2`，兼容导入 v1，与数据库版本独立。导出含业务表、分类和本地图片；设备级导出时间与计数留在本机。恢复使用 Zod 校验结构、数值、日期、ID 唯一性、主业务关联、补给关系和每日范围，再确认整体覆盖；写入失败事务回滚。第一版不支持合并恢复。CSV 支持中文 UTF-8 BOM、引号转义与常见公式注入前缀保护。

出发前建议：

1. 联网打开生产站点，检查「离线资源已就绪」。
2. 在「我的」申请持久存储并导出完整备份到设备文件或你自己的备份位置。
3. 安装主屏幕应用，退出后开启飞行模式，再打开，检查照片、餐食和清单并保存一次编辑。

浏览器可能拒绝持久存储，系统回收或清理站点数据仍可能丢失数据。这是本机保存，不是云端备份；也不支持首次完全断网安装。

## 验证

```sh
npm test
npm run build
npm run test:e2e
```

Playwright 默认使用本机 Windows Chrome。其他系统可以指定 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`，或修改配置使用已安装的 Playwright Chromium。自动化使用隔离的浏览器数据，不加载到用户自己的浏览器中。

1.1 验证命令与验收范围见 `docs/ACCEPTANCE.md`、`docs/UPGRADE-TEST.md`。升级专项需要先准备真实旧版和另一份新构建资源，未准备时会明确跳过。

浏览器自动化运行在 Windows Chrome，手机尺寸通过视口模拟。**尚未进行 iPhone/Safari、Android 主屏幕安装、真实飞行模式/系统杀进程、系统存储回收和新旧 PWA 版本切换的真机验证**，这些不能用桌面测试替代。详细验收见 `docs/ACCEPTANCE.md`。

## 代码位置

- `src/model.ts`：实体、金额/重量/餐食/采购/补给计算。
- `src/db.ts`：Dexie 表和数据库迁移。
- `src/services.ts`：购买、撤销、删除、复制、日期变更等业务事务。
- `src/backup.ts`：备份校验、事务恢复、文件与 CSV 导出。
- `src/Offline.tsx`：Service Worker 注册、更新提示、缓存检查。
- 其余按页面拆分，`src/ui.tsx` 提供表单与基础控件，`src/style.css` 提供响应式户外配色。
- `tests/`、`e2e/`：自动化验证。

## 已知限制

- 仅当前设备/浏览器/站点；无账号、后端、同步、地图、GPS、在线天气、社交或多人分账。
- 照片每张不超过 5 MB，备份导入不超过 200 MB；Data URL 与整份 JSON 需要内存，大型图片库不适合此版本。未引用的旧照片暂不自动清理，避免破坏历史与恢复；可用存储容量由浏览器决定。
- 天气与路线点是手动记录；补给条件需用户核实。食物热量是输入值，不构成专业营养建议。
- 剩余食物复盘是可编辑文本，尚未做逐食物库存扣减。模板可直接编辑，套用前预览，按装备 ID 或临时来源去重。
- 数据恢复仅支持校验后全量覆盖；当前默认站点根路径部署，不适配任意子目录。

## 1.1 优化

- 模板可直接维护名称、备注与条目；套用只补齐缺项，不覆盖已有数量与打包状态。
- 计划中行程支持查看装备快照差异，逐字段确认同步；已出发和完成的行程不提供同步入口。
- 单项直接装包、当前筛选批量装包及约 6 秒精确撤销。
- 统一分类目录、停用和迁移删除；各装备位置统一使用本地照片或内置分类图标。
- 装备多选器保留跨搜索/筛选的选择，事务提交再次去重。
- 我的页面展示真实运行版本与构建、主动检查更新、上次导出及有效修改次数；默认 30 次提醒，可延后一天。

旧版临时物品没有模板来源信息，无法安全反推关联；升级不会凭同名合并或清除旧重复条目。新版模板来源可稳定去重。具体迁移和验收步骤见 `docs/UPGRADE-TEST.md`。
