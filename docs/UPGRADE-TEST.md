# 1.1 升级与离线验收

## 本次兼容策略

- 应用版本 1.1.0，Dexie 数据库从 v2 升级到 v3（底层 IndexedDB 版本 20→30）。保留现有表，新增 `categories` 和设备级 `meta`；旧快照的文字和克重不改写。
- 分类去除首尾空格建立唯一目录，装备/待购共用一套，费用独立。记录新增 `categoryId`；历史分类文字仍保留。重命名通过 ID 维护关联，不自动同步行程的名称、分类和重量快照。
- 模板新增备注，临时模板条目获得稳定 `sourceId`；新建或保存的临时行程条目也有来源 ID。去重先看装备 ID，无装备 ID 时看来源，提交事务内再核验。
- 旧版没有记录临时物品的模板来源，无法可靠反推。迁移为旧条目分别分配稳定来源，不凭名称合并；升级前已经存在的重复条目不会被自动删除。新版保存和套用的临时条目支持稳定去重。
- 备份格式升级到 v2，包含分类、来源和所有业务照片。仍接受 v1 备份，恢复时运行同一兼容迁移。设备级导出时间、提醒阈值和修改计数单独保存在 `meta`，恢复旧备份不会覆盖当前设备的导出历史。
- 每个业务操作和修改计数处于同一个事务；批量一次，失败回滚，无效写入/浏览/取消不计数。导出期间发生的新修改保留在计数内。上次导出仅表示已生成并发起下载，无法保证用户最终保存文件。
- 基于 `stateToken` 关联单项/批量装包撤销；提示约 6 秒有效，批量仅作用于提交时可见的筛选结果。条目若随后改动，旧撤销整批拒绝，避免覆盖新状态。
- 装备同步仅对“计划中”行程开放。每个字段单独选择，确认时核验预览是否过期；价格、数量、备注、必带、携带方式和检查状态不变。

## 运行验证

```sh
npm ci
npm test
npm run build
npm run test:e2e
```

普通端到端验证使用 Windows Chrome 和独立数据目录，390px 模拟手机。其他系统可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 并相应修改测试服务器命令。

完整资源升级测试需要真实旧版构建和第二个当前构建：

```sh
python scripts/prepare-upgrade-test.py
npm run test:e2e -- e2e/upgrade.spec.ts
```

准备脚本下载固定的、实际发布过的 1.0 提交 `ac7a342e98dd4979e74d5b9da127837be96023bd`，只写入 `.tmp`。需要网络及当前已安装的构建工具。第二个当前构建使用不同的编译时构建 ID；不是只改显示文字。未准备资源时该专项测试明确跳过，不算升级验证通过。

升级用例在同一临时 HTTP localhost 源依次托管：

1. 旧版 1.0：加载演示数据、上传照片，确认数据库版本 20、旧 Service Worker 已控制页面。
2. 当前 1.1：下载等待中的 SW，关闭旧页面后重新打开，检查真实运行版本、数据库版本 30、旧快照和照片。
3. 另一份真实 1.1 构建：主动检查更新；存在未保存模板草稿时拦截重启，保存后允许更新。
4. 检查实际新构建 ID 和已保存模板，断网再重开检查装备、照片与本地图标。

## 真机边界

上述是 Windows Chrome 的自动化验证。仍需在华为自带浏览器、Android 主屏幕应用及 iOS Safari 验证安装、真实飞行模式、系统杀进程、更新按钮、下载文件位置、系统大字体和强光可读性。

不要通过清除网站数据来更新。旧客户端首次升级 1.1 时如果仍显示旧界面，可联网打开等待资源下载，再关闭该站点所有页面和主屏幕窗口后重新打开。之后可在「我的 → 版本与数据」主动检查并更新。
